# Session report — 27 August 2026: LoRA transcript scorer, built and run

A fifth scoring arm — a 1.5B instruct model LoRA-fine-tuned on transcripts and decoded
ordinally — built from nothing and evaluated under the project's existing speaker-grouped
protocol inside one day. **The headline is a negative result.** The content-reading arm
reaches **QWK 0.446** (argmax) / **0.415** (expected) against the Random Forest's
**0.558** on identical rows under an identical protocol, finishing below the word-count
Ridge floor of **0.500** that the notebook nominated in advance as its honesty bar.

Recommendation 3 of `reports/evaluation_report.md` is answered along the way, and answered
against the caveat it was raised to test: the ASR-propagation null **replicates** under a
scorer that reads nothing but the transcript (raw r = +0.161, partial r = −0.036), and the
Random Forest row reproduces the published +0.15 → −0.01 to three decimals on the same
rows.

This report is chronological. Everything up to and including the smoke runs is the build;
everything from "The run" onward is measured.

## What I built

- Test suite: 12 tests for the ordinal layer, 13 for the LLM scorer (character-level

## Gold-transcript coverage — measured, and it changed the design

|             | scored | asr.stm | fluent.stm | gec.stm |
|-------------|--------|---------|------------|---------|
| dev P3+P4   |    876 |   68.5% |      67.2% |   67.2% |
| train P3+P4 |  6,065 |   12.0% |       4.6% |    4.6% |

Two consequences shaped the plan:

1. **Gold-only would drop roughly a third of dev** (600 of 876 usable). That is a

Decision: download the dev audio and transcribe it with Whisper, keeping all 876 rows
comparable to the published baseline. Confirmed live and ready to pull:
`data.flac.dev.01.zip` (1.41 GB) + `data.flac.dev.02.zip` (0.62 GB), public S3, 200 OK.
Until that lands, `--transcripts fluent` runs on the 589 gold-covered rows and exercises
every code path — that is how this session's smoke run was done.

## Prompt-parity contract, verified against the real tokenizer

The stub-tokenizer tests proved the code path; a separate pass verified the actual
contract against `mlx-community/Qwen2.5-0.5B-Instruct-4bit`:

- Bands A–H are single tokens, token ids 32–39.
- `assert_prompt_parity` passes: the unmasked training tail is exactly `E<|im_end|>` —
  3 tokens past a 77-token inference prefix.
- A right-padded batch forward pass returns `(3, 8)` rows summing to 1.

This matters because the training/inference contract is unforgiving:
`mlx_lm.tuner.datasets.CompletionsDataset` builds exactly `[user, assistant]`, and with
`--mask-prompt` the loss offset is `apply_chat_template(messages[:-1],
add_generation_prompt=True)`. Inference has to rebuild exactly one user message, no
system message — a system message at inference diverges silently, nothing errors, QWK
just sags. `--mask-prompt` is required; without it the model spends its capacity
reproducing transcripts instead of learning the band.

## Per-fold training script, smoke-tested end to end

`scripts/finetune_lora.py` runs `mlx_lm lora` as a **subprocess per fold**, which was a
deliberate choice after auditing the installed MLX source for per-process state hazards:

- The model must be reloaded every fold — `linear_to_lora_layers` raises on an
  already-converted layer, and `remove_lora_layers` only strips `LoRALinear`, not
  embedding/switch/DoRA variants.
- The seed must vary per fold — `mx.random.seed`/`np.random.seed` are process-global, so
  a fixed seed reproduces identical LoRA init *and* identical batch order across folds.
- `--adapter-path` must be namespaced per fold — `adapter_config.json` is overwritten
  unconditionally at the start of training with no fold suffix.
- `--resume-adapter-file` restores adapter weights only, not optimizer state.
- LoRA rank/scale/dropout are YAML-only (`lora_parameters`); a partial dict raises
  `KeyError` rather than falling back to defaults (8 / 20.0 / 0.0).
- `--grad-checkpoint` patches the layer class and re-wraps on every call — avoid it in a
  per-fold loop, it silently compounds.

Running each fold as its own subprocess sidesteps all of these structurally rather than
relying on careful bookkeeping inside one long-lived process.

## Smoke run — the compression prediction, confirmed early

A **20-iteration smoke test**, 0.5B model, 4 LoRA layers, fold 0 only, gold `fluent`
transcripts (589 responses / 299 speakers, 118 test rows). This is a pipeline check, not
a result — 20 iterations is not training. Val loss went 10.5 → 0.52.

| decode   | r     | QWK   | prediction range |
|----------|-------|-------|-------------------|
| expected | 0.313 | 0.000 | 3.84 – 3.98       |
| argmax   | 0.255 | 0.106 | 3.5 – 4.0         |

Mean band probability peaks at D/E after only 20 iterations — the model is learning the
corpus *marginal* first, which is what a 20-iteration budget buys, not the ordinal
relationship. The finding worth carrying into the real run: **expectation decoding can
produce r > 0 with QWK exactly 0.** `evaluate` snaps predictions to the 0.5 grid, and a
sufficiently compressed continuous prediction collapses into a single class — kappa then
equals a constant predictor's kappa, even though the correlation says there is some
signal. This is band compression in its most extreme form. It means notebook 05 has to
report r and QWK together with the prediction range, because QWK alone would read as "no
signal" when r says otherwise. The stored `probs` are kept so re-decoding at another
temperature, or after a linear rescale, costs nothing later. Scratch artefacts from this
run sit at `data/derived/lora/smoke/` (gitignored); the smoke OOF cache itself was
deleted so it cannot be mistaken for a real result.
## The 1.5B smoke — memory fits, and it settles the iteration budget

Four iterations, fold 0, gold `fluent`, on the model the real run would use. The OOF cache
was deleted afterwards so it could not be mistaken for a result.

- **Peak memory 3.238 GB** on an ~8 GB machine, comfortable even with Whisper holding
  1.1 GB beside it — MLX runs on the GPU while faster-whisper int8 stays on CPU, so the
  transcription running concurrently was not slowed. The 0.5B smoke peaked at 2.07 GB.
- Trainable 0.171% (2.638M / 1543.714M). Throughput ~0.92 it/s, so 400 iterations is
  ~7 minutes of training per fold and ~15 minutes per fold all in.
- **Trained tokens: 64 over 4 iterations, ~16/iteration** — the `--mask-prompt` contract
  working. Only the completion (`E<|im_end|>`, 3–4 tokens) is unmasked, times batch 4. A
  much larger number here would have meant the mask was silently not applied.

Val loss fell 9.395 → 2.077 → 0.577 → 0.658 in four iterations, and that collapse is not
the evidence it first looks like. The loss covers only the ~3 unmasked completion tokens,
so almost all of it is the model learning the *output format* — emit one letter in A–H,
then stop — which is nearly exhausted by iteration 4. It is a plumbing check, not a
quality one. 400 iterations × batch 4 against ~631 training rows per fold is **~2.5
epochs**, an ordinary LoRA budget at rank 8 on 8 layers, so the budget was left alone.

Two things follow that mattered later. A low val loss does not mean a useful scorer:
0.577 is below ln(8) = 2.08, which only says it has beaten uniform, and a model that
confidently always emits the modal band scores well on it too — exactly the 20-iteration
failure. And `save_every` is set to `iters`, so **only the final adapter is kept**; the
val checkpoints are diagnostic, with no best-checkpoint to fall back on.

## Notebook 05, dry-run before the data landed

The notebook had never been executed, and discovering its bugs after a six-hour pipeline
would have been the expensive way to find them. Its code cells were run verbatim against
a **synthetic** OOF cache — real schema, real band marginal, fabricated numbers that never
touched `data/derived/`. All cells executed clean, and two behaviours were confirmed
rather than assumed: prediction range narrows monotonically as temperature rises, showing
the logit-scale recovery in section 5 is not double-applying the run's own temperature;
and `argmax` is invariant to temperature, as that cell claims in print.

Three further checks, each of which would have cost hours if left to the real run:

- **The `--transcripts whisper` path** — untested until then, since the smoke runs used
  gold `fluent`. Exercised against the 250 P3 transcripts available at the time: prompt
  parity holds on the whisper path too, and **prompt tokens run to a median of 168 and a
  maximum of 269 against `max_seq_length` 1024**. This was the last silent-corruption risk
  in the config: mlx-lm truncates over-long sequences without complaint, and a truncated
  transcript would have degraded some folds more than others. There is ~4× headroom.
- **`extract_prosody.py` was missing from the plan.** Notebook 05's comparison section
  rebuilds the notebook-03 feature matrix, which reads `prosody_{part}_full.json`.
  Omitting it would have failed the comparison *after* transcription and training were
  already spent.
- **The default kernel does not work.** The notebook records `kernelspec.name = "python3"`,
  and the only kernelspec on this machine is Anaconda's, which lacks `speechlab`, `mlx`,
  `mlx_lm` and `soundfile` — but *has* `sklearn`, which is what would have made the
  failure look like a notebook bug rather than a kernel one. Rather than install into the
  user's home, a kernelspec pointing at the venv lives in the scratchpad and is selected

## Result — the whisper arm, 5/5 folds, 876 responses, 438 speakers

The protocol is identical to notebook 03, and notebook 05 does not re-run `GroupKFold`
for the sklearn arms — it reads the fold index out of the LoRA cache and hands it to
`cross_val_predict` as an explicit split, so every arm below is scored on exactly the same
held-out rows. Notebook 03 already documented how much fold assignment can move a number;
re-splitting and hoping it matched would have quietly undermined the comparison.

```
                  pearson_r  spearman   MAE    RMSE    QWK   pred_range
Random Forest       0.622     0.625    0.456  0.575  0.558     2.38
Ridge               0.609     0.610    0.464  0.582  0.548     2.89
word-count Ridge    0.589     0.599    0.474  0.593  0.500     2.93
```

The negative result is stronger than "loses to the Random Forest": the fine-tuned
transcript scorer is **last of the four real arms**, under the floor the notebook itself
nominated. `pred_range` is the mechanism — 1.72–2.00 against 2.38–2.93.

Per-fold expected QWK runs 0.441 / 0.259 / 0.448 / 0.348 / 0.538. **No single fold is

## The decode premise was wrong, and measurably so

`argmax` **beats** `expected` on QWK (0.446 vs 0.415) while *losing* on correlation
(0.505 vs 0.550). The two decodes trade ranking accuracy against scale fidelity: expected
orders candidates better and compresses harder (predicted sd 0.39 against argmax's 0.49,
both under the human 0.73), and QWK — computed on the snapped 0.5 grid — charges for
compression where Pearson r does not. Per fold the split is 2–2.

This is the trade `ordinal.py` was written to make measurable, and it came out against the
design's assumption that expectation decoding would be the arm's result. **Both decodes are
reported; neither is "the" result.** An interim reading blamed fold 1's inversion on its
bimodality; that does not survive fold 3, which is not bimodal and still favours argmax by
0.145. Compression, not bimodality, is the mechanism.

Band-edge compression is worse than the Random Forest's, against notebook 04's
+0.96 / −0.70:

| band | Random Forest | LoRA (expected) | LoRA (argmax) |
|---|---|---|---|
| 2 | +0.964 | **+1.028** | +0.917 |
| 5 | −0.701 | **−1.012** | −0.973 |

Exact agreement 27.6% (argmax 30.5%) against the Random Forest's 34.0%.

The temperature sweep measures the same account rather than asserting it:

```
   T     QWK    pred_range          argmax QWK 0.446, temperature-invariant
 0.25   0.449     1.879
 0.50   0.436     1.741
 1.00   0.415     1.721
 2.00   0.374     1.551
```

QWK rises monotonically as the distribution sharpens while r stays flat at ~0.55 —
temperature moves scale, not ranking. Sharpening recovers only ~+0.03 QWK, roughly to the
argmax level, and then runs out: predicted sd at T = 0.25 is still 0.40 against the human
0.73. **T stays at 1.0 in the reported arm.** Selecting 0.25 off this table would be
tuning on the evaluation set and would inflate the figure standing next to 0.558.

## Fold 1 collapsed, and three of five folds ended on degraded weights

Fold 1's argmax marginal was `[0, 0, 63, 0, 113, 0, 0, 0]` — every response on 3.0 or 4.0,
nothing on 3.5, one of the two commonest human scores. That is the failure mode flagged in
advance as disqualifying however good the loss looks, and it happened once in five folds.
It is reported, not averaged away.

End-of-run val loss against each fold's iteration-300 checkpoint:

```
fold 0   0.439 → 0.418   at minimum        fold 3   0.411 → 0.448   +0.037
fold 1   0.408 → 0.437   +0.029            fold 4   0.400 → 0.398   at minimum
fold 2   0.392 → 0.430   +0.038
```

Three degrade in the last quarter, two are neutral (an interim note called it universal
after four folds; fold 4 disproved that). The fix is therefore **not** shortening to
`--iters 300`, which gains nothing on folds 0 and 4, but setting `save_every` finer than
`iters` so a best-checkpoint fallback exists at all. As it stands three folds are scored on
weights measurably worse than ones the run passed through, which makes the pooled 0.446 a
mild *under*-estimate — the safe direction for a headline.

## Recommendation 3, answered — and one cell was measuring the wrong quantity

The report states its +0.15 alarm in terms of **signed** error. The cell as drafted
correlated WER against **|error|**, which is a different question — signed error asks
whether bad transcription pushes scores in a *direction*, absolute error asks whether it
makes them less accurate either way — and it would have been written up as a
non-replication. The cell now prints both, signed first, and the surrounding markdown
explains why the qualifier is load-bearing.

```
                     WER vs SIGNED error         partial (proficiency controlled)
Random Forest        +0.151 (p=.0002)            −0.014 (p=.733)
  report says        +0.15  (p=.0002)            −0.01  (p=.75)
LoRA (expected)      +0.161 (p=.0001)            −0.036 (p=.379)
LoRA (argmax)        +0.117 (p=.0040)            −0.068 (p=.095)

                     WER vs |error|              partial
Random Forest        −0.031 (p=.444)             −0.022 (p=.590)
LoRA (expected)      −0.083 (p=.043)             −0.001 (p=.987)
```

All three arms show the same mediation: a significant raw WER-to-error correlation that
collapses to nothing once proficiency is controlled. **The report's null was not an
artefact of content-blind features, and the caveat it closes on does not survive testing.**
The Random Forest row reproducing the published figure to three decimals also validates
the whole path — same rows, same WER computation, same partial-correlation code.

## The interventional arm is confounded, and the claim was withdrawn

The gold-transcript retrain (`--transcripts fluent`, 589 responses / 299 speakers,
5/5 folds) was described in the notebook as changing the input and holding everything else
fixed. It does not. Three things differ, and only the first is the variable of interest:

| | whisper arm | gold arm | |
|---|---|---|---|
| transcript source | Whisper small | gold `dev-fluent.stm` | ← intended |
| rows per training fold | 630 | 425 | ← 32% less supervision |
| epochs at 400 iters × batch 4 | ~2.5 | ~3.8 | ← more overfitting |

All three push the same way, so "gold scores lower" is uninterpretable as evidence about
transcript quality. Matched on the 589 rows both arms scored:

```
                    pearson_r  spearman_rho    MAE   RMSE    QWK
Whisper (expected)      0.503         0.509  0.535  0.657  0.368
gold (expected)         0.413         0.428  0.518  0.651  0.345
Whisper (argmax)        0.455         0.470  0.532  0.684  0.395
gold (argmax)           0.291         0.329  0.560  0.739  0.248
```

Fold 0 of the gold arm ended +0.040 above its own best val, the largest end-of-run uptick
anywhere in either run — the epoch gap showing up in the data rather than merely in the
arithmetic.

Hyperparameters were still held at their defaults deliberately: equalising epochs by
lowering `--iters` would have confounded transcript source with training budget, swapping
one confound for another. **The strongest claim this design supports is that gold
transcripts do not help enough to overcome a smaller training set** — weaker than what the
section originally promised. The claim is withdrawn in the notebook rather than quietly
softened, and the clean control (Whisper transcripts restricted to the same 589 rows, so
the arms differ only in transcript source) is named as outstanding work. The correlational
test above is unaffected by any of this and answers Recommendation 3 on its own.

## Licence check on the committed outputs

Notebooks 01–04 are committed **with** outputs, so the convention is not "no outputs" but
"no corpus content in the outputs". Notebook 05 was executed `--inplace` and checked cell
by cell rather than assumed: `utt`, `speaker` and the transcript caches are used
internally — dataframe construction, merges, a uniqueness assertion — and never reach the
display channel. Every trailing expression is an aggregate: band histogram, per-fold counts,
metric tables, printed summary statistics, two **binned** figures, the temperature sweep,
the correlation printout. Re-measured against the corpus itself across the notebook's
full text output: **0 utterance ids, 0 speaker ids, 0 verbatim five-word transcript
runs.**

The signed-error figure is worth calling out as the one place a per-response scatter would
naturally have gone; it plots binned means instead, so not even anonymous per-response
points are committed. The check to re-run if the notebook changes is whether any new cell
ends in a bare row-level expression — a `.head()`, a raw dataframe, a `to_string()`.

Separately: the LoRA adapters stay local. The licence forbids releasing corpus-derived
models without approval, and an adapter trained on learner transcripts is a derivative —
hence the `.gitignore` rule for `adapters/`, `*.safetensors`, `*.npz`, `*.gguf`. Local MLX
is the compliant architecture for the "do not share with LLMs with training retention"
clause, not a hardware compromise.

## Findings

1. **Content does not help here — it does not even clear the word-count floor.** QWK 0.446
   (argmax) / 0.415 (expected) against the Random Forest's 0.558 on identical rows, last of
   the four real arms and below the 0.500 floor nominated in advance. It is a genuine
   negative result rather than a broken pipeline: pooled r = 0.55 is real signal and
   per-fold QWK ranges 0.259–0.538, so the arm ranks candidates — it just ranks them less
   well than fluency timing does, on 876 responses at 1.5B and rank 8.
2. **The ordinal decode premise was wrong.** argmax beats expected on QWK while losing on
   correlation, because the decodes trade ranking accuracy against scale fidelity and QWK
   charges for compression where r does not. Both are reported.
3. **Recommendation 3 is answered, and the report's null survives.** A scorer that reads
   nothing but the transcript reproduces the same mediation (+0.161 → −0.036), and the
   Random Forest row reproduces the published +0.15 → −0.01 to three decimals.
4. **Compression is worse than the Random Forest's**, +1.028 / −1.012 at the band edges
   against +0.96 / −0.70 — the failure mode that makes a scorer unsafe to use unsupervised,
   amplified rather than fixed by reading content.
5. **One fold in five collapsed** to two output classes, and three of five ended on weights
   worse than ones the run passed through. Both are protocol findings, not noise.
6. **The gold-transcript ablation is confounded** and its causal claim was withdrawn.
