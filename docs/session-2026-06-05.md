# Session report — 5 June 2026: ASR error analysis and prosody features

## What I built

Notebook 02 (`notebooks/02_wer_and_prosody.ipynb`): word error rate against the corpus's gold transcripts, ground-truth quantification of Whisper's disfluency erasure, five ASR-independent prosody features extracted with Praat/parselmouth, and MTLD replacing the flawed TTR feature — all evaluated under the identical cross-validation protocol as notebook 01 so every number is directly comparable.

## WER methodology

The gold transcripts mark filled pauses (`(%hesitation%)`) and partial words; Whisper transcribes neither. I therefore computed WER two ways: **lenient** (disfluency tokens removed from the reference — content-word accuracy on like-for-like terms) and **strict** (kept — a transcript feeding a *fluency* scorer arguably should contain them). The gap between the two is the disfluency erasure cost expressed in alignment terms. Only 65 of the 100 sampled responses have gold transcripts — the corpus annotates a subset of the dev set — so the WER analysis is scoped to those and says so.

## Findings

| Model | Pearson r | MAE | QWK |
|---|---|---|---|
| Word-count Ridge | 0.648 | 0.418 | 0.580 |
| Fluency Ridge (nb01, TTR) | 0.671 | 0.433 | 0.621 |
| **Fluency Ridge (MTLD)** | 0.660 | 0.431 | **0.647** |
| Prosody-only Ridge | 0.331 | 0.550 | 0.210 |
| Fluency(MTLD) + prosody | 0.651 | 0.446 | 0.644 |

1. **Corpus WER is 16.8%** (lenient), but the per-response mean (22.2%) is nearly double the median (12.1%) — a tail of responses is transcribed very badly. Keeping disfluencies adds +4.1% WER.
2. **WER rises as proficiency falls** (r = −0.28): ASR noise concentrates on exactly the speakers a scorer most needs to get right. Feature quality is systematically worse for weaker candidates — this becomes a core thread of the fairness analysis.
3. **The erasure is now measured, not inferred.** Gold annotations show 333 filled pauses actually spoken against 0 in Whisper output, and the erased signal is genuinely predictive (gold disfluency rate vs score: r = −0.25, p = .046). A Whisper-fed scorer is blind to a real proficiency cue.
4. **MTLD fixed the TTR artefact** — r = +0.34 with the right sign versus TTR's −0.23 — and lifted QWK from 0.621 to 0.647, the best model so far.
5. **Prosody added nothing at n = 100** — a null result I kept and reported rather than discarded. The strongest prosody correlate (`intensity_sd_db`, r = −0.34) is plausibly a recording-gain confound, so I flagged it for the audio-quality fairness slice rather than trusting it as a scoring feature.

## A reproducibility trap caught

My first run produced QWK 0.579 for the supposedly identical notebook-01 feature set (published: 0.621). The cause: I loaded the sample in file-list order rather than reproducing notebook 01's stratified sampling, and row order determines the K-fold split. A ±0.04 QWK swing from fold assignment alone at n = 100 is itself worth knowing. I fixed it by reproducing the sampling code exactly (same seed, same order), after which notebook 01's numbers reproduced to the third decimal.

## Tools and decisions

`jiwer` for WER with a single shared normalisation on both sides (case, punctuation) so contractions don't count as errors; `praat-parselmouth` for pitch and intensity, with pitch spread measured in **semitones** (log-scale, comparable across voices) rather than Hz; intensity means deliberately excluded as untrustworthy across recording devices, only the spread used; prosody extraction cached to gitignored `data/derived/` alongside the transcripts.

## Afternoon: refactor into the `speechlab` package

With two notebooks of duplicated helpers, I extracted the proven code into a proper src-layout package (`src/speechlab/`): `data` (corpus loading, the notebook-01 stratified sampler), `asr` (transcription with a resumable JSON cache, STM parsing, lenient/strict WER), `acoustic_features` (fluency from word timestamps, prosody via parselmouth), `text_features` (token normalisation, TTR, MTLD) and `evaluation` (grid snapping, the five-metric scorer report). Heavy imports (faster-whisper, jiwer, parselmouth) are lazy, so the package imports cleanly in any context. Notebooks 01 and 02 stay frozen as session records; new work imports the package.

Two quality gates before committing:

- **A 23-test pytest suite on entirely synthetic fixtures** — generated sine waves for prosody (the 220 Hz tone must come back as f0 ≈ 220), hand-written STM text, known-value MTLD and QWK cases. No corpus data appears in tests, keeping the licence boundary intact.
- **An equivalence check**: the package reproduces notebook 02's results (QWK 0.621 / 0.647 / 0.644) to the third decimal — the refactor changed structure, not behaviour.

The tests immediately earned their keep: MTLD returned 0 for text so diverse it never completes a factor — maximally diverse text scored as minimally diverse. Unreachable on real speech (function words always repeat), so notebook 02's numbers stand, but the boundary is now correct (caps at text length) and pinned by a test.
